# Paseo SBX Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 기존 Paseo에서 선택·자동 위임 가능한 여섯 sbx 템플릿을 생성한다.

**Architecture:** 고정된 공식 이미지를 기반으로 에이전트별 도구를 설치한다. 호스트
Go launcher가 sbx stdio 실행을 중계하고, 세션별 HTTP MCP proxy로 sandbox
provider 간 위임만 허용한다. credentials는 호스트 proxy 메모리에 유지한다.

**Tech Stack:** Docker/Buildx, sbx 0.46.0+, Paseo 0.10.1+, Go 표준 라이브러리,
Node.js, Codex 및 Claude Code native plugins.

**Spec:** ../specs/2026-09-30-paseo-sbx-design.md

## Global Constraints

- provider 이름은 spec의 여섯 이름을 사용한다.
- workspace 절대 경로를 보존하고 host home·Docker socket을 mount하지 않는다.
- plugin revisions, npm versions, base image digests를 고정한다.
- protocol stdout에는 JSON 이외의 안내를 추가하지 않는다.
- 초기 이미지에 credentials·개인 session을 넣지 않는다.
- 자동 위임 대상은 여섯 provider, 작업 위치는 caller workspace로 제한한다.
- GitHub/GHCR 게시는 이번 작업에 포함하지 않는다.

## Review Focus

- 공백·따옴표가 포함된 cwd와 args: shell 재평가 없이 배열로 전달.
- JSON과 SSE로 반환되는 MCP 응답: 같은 필터 적용, session header 유지.
- 기존 sandbox 재사용: 이미지/profile/workspace 일치 여부 확인 후 재사용.
- agent 중단과 재시작: relay, child process, network rule 정리.
- 모델 인증 부재: runtime 설치 성공과 실제 모델 실행 성공을 구분.

## Execution decisions

사용자는 설계 본문을 확인하고 “자동 위임도 포함해서 진행”을 요청했다. 그 승인으로
구현을 이 세션에서 계속한다. 새로운 독립 프로젝트 디렉터리에서 작업한다. 추가
설계 승인 질문을 반복하지 않는다. 로그인은 사용자 브라우저 작업이 필요하므로
비동기로 요청하고 인증과 독립적인 빌드·구현을 계속한다.
